Observability Architecture & 3 Pillars

This implementation instruments the AI-based Village Pond Planning backend following OpenTelemetry standards:

  • Distributed Tracing: Ingress HTTP requests are intercepted by FlaskInstrumentor. Within the request, custom child spans are dispatched for contour parsing, bicubic DEM generation, flow routing, catchment BFS, and Pareto scoring.
  • Runtime Metrics: PrometheusMetricReader converts OpenTelemetry counter and histogram instruments into standard Prometheus metrics served on /metrics.
  • Log Correlation: TraceContextLogFilter dynamically queries active span contexts to inject trace_id and span_id into all log records, linking logs to traces.

Computational Latency Breakdown

OpenTelemetry tracing isolates the computational stages in the hydrological pipeline:

  • kml_parser.parse_contours: I/O and parsing of 3D contour vertices.
  • dem_builder.build_dem: Grid interpolation constructing the elevation surface.
  • terrain_analysis.flow_routing: D8 flow routing, flow accumulation, river detection, and exclusion zone buffering.
  • catchment.find_pond_candidates: Reverse BFS catchment delineation from candidate depression pour points.
  • pond_selector.score_and_select: Multi-criteria evaluation, rainfall querying, and candidate ranking.
