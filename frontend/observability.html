1. The 3 Pillars of Observability in this Project

OpenTelemetry standardizes telemetry collection into three correlated pillars:

  • Distributed Traces: Tracks requests through end-to-end execution. Each pipeline run creates a parent span (`pond_analysis.pipeline`), containing nested child spans for KML parsing, DEM raster generation, flow direction/accumulation, catchment delineation, Pareto scoring, and GeoJSON building.
  • Metrics: Numeric quantitative measurements collected at runtime (request counts, duration histograms, pond candidate counters, DEM raster size) exported via standard Prometheus format at /metrics.
  • Logs: Event logs linked directly to traces via trace_id and span_id injection in log records, enabling instant correlation between errors and execution traces.

2. Instrumenting the Hydrological Pipeline

The core pipeline spans captured by OpenTelemetry in app.py:

  • kml_parser.parse_contours: Records input KML/KMZ path, contour count, and elevation boundaries.
  • dem_builder.build_dem: Records raster resolution (e.g. 120m), grid shape, min/max elevations.
  • terrain_analysis.flow_routing: Measures D8 flow direction, flow accumulation, river detection, and exclusion zone buffering.
  • catchment.find_pond_candidates: Measures uphill reverse BFS catchment solver and candidates found.
  • pond_selector.score_and_select: Records multi-criteria scoring, Pareto selection, and external OSM road distance queries.
  • geojson_builder.build_geojson: Measures final spatial GeoJSON construction.

3. Why OpenTelemetry is Essential for Systems

During the VIVA, explain that OpenTelemetry eliminates "blind spots" in backend services:

  • Performance Bottleneck Identification: The waterfall visualizer immediately shows which stage consumes the most time (e.g., DEM interpolation vs. hydrological catchment BFS).
  • Root Cause Analysis: If contour parsing or river masking fails, the span is marked with status ERROR, capturing the exact exception stack trace and parameters.
  • Standardized & Vendor-Neutral: Works with Jaeger, Prometheus, Grafana, Datadog, or native Python exporters without rewriting application logic.
